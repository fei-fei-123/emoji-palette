# 测试报告

这个文档是我进行测试后的问题总结，接下来逐步解决这个文档中的问题。

注意：本报告中的优先级，并不是指要优先做，最后做。而是如果此功能与其他功能有冲突，则可以做相应的妥协，甚至可以接受阉割掉这个功能。

# 问题

## 面板需要背景

当前面板没有任何背景的存在，导致以下问题

1. 没有办法更好的区别前台与后台，用户体验极差
2. 鼠标滚动时，如果指针没有定向到emoji，则无法正常滚动（事件穿透到了后方的应用层）

趁着这个机会可以对整体面板进行重构。要求如下

1. 面板整体样式保持不变：简约，直观
2. 整体控件添加些许透明度，显得比较高端，不过要注意，emoji不能被透明度影响，必须不透明。并且需要平衡透明与用户体验
3. 深色与浅色都要进行适配

## 用户控制体验不好

此部分整体没有什么原则性问题，但存在不少小细节需要进行打磨，这里分成几个章节进行详细说明

### 用户控制相关

当前控制逻辑糟糕，虽然解决了指针冲突问题值得表扬。但同时引入了新的问题。

1. 控制不够直观：左右控制光标，上下控制选择（左右切换），这里的操作逻辑略微反人类。

我认为，搜索不应该直接成为焦点。默认焦点应该直接聚焦于面板，左右控制符号的左右选择，上下控制符号的上下选择

用户输入文本后，焦点直接进入文本框并输入。此时：上下进入面板（文本框失去焦点，后续操作变回左右控制符号的左右选择，上下控制符号的上下选择）。左右控制文本符号

2. 切换分类依赖鼠标

这里确实是小问题，实现优先级可以降低。不过，我依然希望可以操作逻辑自洽：使用+-来控制面板，+（也就是键盘上=+键）进入下一个分类，-（也就是键盘上-_键）进入上一个分类。

3. 输入文本后无法切换分类

虽然逻辑上，切换分类与输入文本搜索功能两两互斥，但如果没有任何提示则只会为用户带来疑惑

暂时先这样改：当切换分类后，直接清空文本框（清空文本框后，限制自然解除）。也就是：收到切换分类事件->清空文本框->切换分类。

### 用户行为相关

这里则是对于程序行为的部分调整。部分行为不够友善，整体优先级较低，如果不好处理可以做妥协。

1. 输入符号后面板消失

天然无法解决连续输入多个符号的问题。可以在面板里添加一个设置，输入符号后是否消失面板，亦或者同时按shift+enter则不关闭面板，直接输入。这两个最好都能可以配置。

2. 快捷输入（::shit + space）的方式不够直观

这里因为存在BUG没法测试，但我想了下，我认为不应该采取直接上屏，靠用户猜的方式进行。

这里需求改一下，当输入::后，直接进入快捷输入状态。此状态下有一个特殊的面板。

面板类似输入法，是一个长条型，上面罗列若干个emoji（优先常用）。当输入s的时候，进行筛选，将以s开头的符号与名称展示到下面，如：

💩  ⏫        ...
shi shang      ...

以此类推，输入数字快速上屏。左右光标被劫持到面板里，左右选择符号，空格上屏。

点击外部、上下或者esc关闭面板。无命中虽然不关闭面板，但需要有特殊提示
